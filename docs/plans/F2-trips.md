# F2 — Trips · Plan

_Status: Approved · Last updated: 2026-11-19 · Spec: [F2-trips.md](../specs/features/F2-trips.md) (Approved 2026-11-19)_

## Approach
F2 adds the trip record and the four trip operations (create, list, get one, delete), all for the logged-in user. Pure rules go in `src/domain/`: the name check (trim, blank, 100 characters), the newest-first order, the created-date format, the copy, and the delete-dialog choice. None of these import the database, Next.js, iron-session or argon2. Each trip operation is a service in `src/services/` that receives the session, the `TripStore` port, `now`, `newId` and the logger. Every service calls `requireUser` (F1.T15) first, so the owner always comes from the session and never from the request (F2.R5, F2.R11). The Drizzle store in `src/db/` is the only code that writes SQL. Each query filters by `owner_id`, and the delete runs in one transaction. Cascades come from the database: the `trips` table is the parent that later child tables reference with `ON DELETE CASCADE` (F3–F6). The route handlers in `src/app/api/trips/` only parse the request, call a service and map the result to a status code. The pages `/trips`, `/trips/new` and `/trips/[id]` are client components that call those routes, because the list needs a loading state and the form and dialog need in-flight states. The access gate in `src/auth/gate.ts` is changed so `/api/*` is answered by the handler (401 JSON) and not by a page redirect (F2.AC12).

**Build dependency:** the project scaffold, logger, config, session, database client and `requireUser` are built by F1 (F1.T1–T20). F2 starts after F1 is built. The scaffold is F1.T1, so F2 has no setup task of its own (see Decisions log).

## Data model changes
One new table, `trips` (migration generated by Drizzle; human approval required):

| Column | Type | Constraints |
|---|---|---|
| `id` | TEXT | PRIMARY KEY (UUID from `newId`) |
| `owner_id` | TEXT | NOT NULL, REFERENCES `users(id)` (no cascade; users are not deleted in the MVP) |
| `name` | TEXT | NOT NULL, CHECK (`length(name) BETWEEN 1 AND 100`); stored trimmed |
| `created_at` | TEXT | NOT NULL (ISO 8601, UTC) |

Index: `trips_owner_created` on (`owner_id`, `created_at`) for the list query.

Cascade: the `trips` table has no children yet. Deleting a trip removes its people, expenses and payments (F2.R9). Each of those tables, added in F3–F6, must declare `trip_id REFERENCES trips(id) ON DELETE CASCADE`. `deleteForOwner` runs the trip delete in one transaction, so the database cascade handles the children. The F3–F6 plans must carry this rule forward. `src/db/client.ts` sets `PRAGMA foreign_keys = ON` explicitly, so the cascade does not depend on a driver default.

## Routes and API
All under `/api/trips`. Bodies are JSON. Errors use F1's shape `{ "error": { "code": string, "field"?: "name" } }`. Every route requires a logged-in session (F2.R11). A logged-out request gets `401` with `code` `not_logged_in`.

| Method and path | Request | Success | Errors |
|---|---|---|---|
| `GET /api/trips` | none | `200 { "trips": [{ id, name, createdAt }] }`, newest first, `createdAt` ISO UTC | `401` `not_logged_in` |
| `POST /api/trips` | `{ name }` | `201 { "trip": { id, name, createdAt } }` | `400` `blank_name` or `name_too_long` (`field` `name`); `400` `invalid_body` for unparseable JSON; `401`; `500` `internal` (no body or name logged) |
| `GET /api/trips/[id]` | none | `200 { "trip": { id, name, createdAt } }` | `404` `not_found` for a trip owned by someone else **or** missing (identical body, F2.AC8); `401` |
| `DELETE /api/trips/[id]` | none | `200 { "ok": true }` | `404` `not_found` (also for a second delete, F2 edge case); `401`; `500` `internal` |

Routes map service results: `not_logged_in` → 401, `not_found` → 404, validation → 400.

## Screens
- **Trips list** (`/trips`, replaces the F1 placeholder): client component. States: loading ("Loading your trips…"); empty ("You have no trips yet." and a "Create trip" button to `/trips/new`); loaded (one link per trip, newest first, each row shows the name and the created date from `formatTripDate`). Failed: "We couldn't load your trips. Try again." and a "Try again" button that fetches the list again and shows loading while it does; no trips are shown with the message (F2.AC15).
- **Create trip** (`/trips/new`): client component. One field, "Trip name", with a visible label. Errors come from `trip-messages.ts` ("Enter a trip name." / "Trip names can be up to 100 characters.") and are linked with `aria-describedby`. A failed request shows "We couldn't save your trip. Try again." and keeps the typed name. While in flight, the button is disabled and reads "Saving…". On success, the user goes to `/trips/<id>`.
- **Trip page** (`/trips/[id]`): client component. Loaded: the trip name and a "Delete trip" button. Not found or not theirs: "Trip not found." / "We couldn't find that trip." and "Back to trips". Loading: "Loading trip…". Failed (any failure other than not-found): "We couldn't load this trip. Try again." and a "Try again" button that fetches the trip again and shows loading while it does (F2.AC16).
- **Delete dialog** (on the trip page): native `<dialog>` opened with `showModal()`, which traps focus and closes on Escape. Title "Delete [trip name]?", body and buttons as in the spec. Confirm sends `DELETE`, the button reads "Deleting…" and is disabled; success goes to `/trips`; failure shows "We couldn't delete this trip. Try again." and the trip stays. Cancel or Escape changes nothing. Focus returns to the "Delete trip" button when the dialog closes.

## Tasks

### F2.T1 — Trip name rules
- **Files:** `app/src/domain/trip-name.ts`, `app/tests/domain/trip-name.test.ts`
- **Depends on:** F1.T1 (project scaffold)
- **Work:** Pure function `validateTripName(raw: unknown)`. A non-string or a name that is empty after `trim()` returns `{ ok: false, code: "blank_name" }`. A trimmed name longer than 100 characters returns `{ ok: false, code: "name_too_long" }`. Length counts code points (`[...name].length`), the same rule F1.T3 uses for passwords. Valid input returns `{ ok: true, name }` with the trimmed name. Inner spaces are kept as typed.
- **Tests:** `tests/domain/trip-name.test.ts`: `F2.AC1 accepts a name of 1 character`, `F2.AC2 refuses an empty name`, `F2.AC2 refuses a name of only spaces`, `F2.AC3 accepts a name of exactly 100 characters`, `F2.AC3 refuses a name of 101 characters`, `F2.AC4 removes leading and trailing spaces`, `F2.AC4 keeps spaces inside the name`.
- **Done when:** `npm test` passes the file.

### F2.T2 — Trip view rules and copy
- **Files:** `app/src/domain/trip-view.ts`, `app/src/domain/trip-messages.ts`, `app/tests/domain/trip-view.test.ts`, `app/tests/domain/trip-messages.test.ts`
- **Depends on:** F2.T1
- **Work:** `sortNewestFirst(trips)` orders by `createdAt` descending, then by `id` to keep the order stable. `listState(request)` takes the list request as `{ status: "loading" }`, `{ status: "failed" }` or `{ status: "loaded", trips }`, and returns `"loading"`, `"failed"`, `"empty"` (no trips) or `"loaded"`. `tripPageState(request)` takes the trip request as `"loading"`, `"not_found"`, `"failed"` or `{ status: "loaded", trip }`, and returns `"loading"`, `"not_found"`, `"failed"` or `"loaded"`. Not-found is its own state, so it is never shown as a failure (F2.AC8, F2.AC16). `formatTripDate(iso, timeZone)` returns "18 Nov 2026": it reads the year, month and day in the given IANA time zone with `Intl.DateTimeFormat(...).formatToParts`, then maps the numeric month to a fixed English abbreviation array, so the result does not depend on the user's locale (F2.R7). The time zone is passed in, not read from the environment. `deleteDialogChoice(choice)` returns `{ callDelete: true }` only for `"confirm"`. `trip-messages.ts` exports the copy from the spec's States & errors, word for word, including the list and trip-page loading and failure copy (F2.AC15, F2.AC16).
- **Tests:** `tests/domain/trip-view.test.ts`: `F2.AC6 sorts trips newest first`, `F2.AC7 an empty list gives the empty state`, `F2.AC6 a non-empty list gives the loaded state`, `F2.AC15 a list request in flight gives the loading state`, `F2.AC15 a failed list request gives the failed state`, `F2.AC8 a not-found trip request gives the not-found state`, `F2.AC16 a trip request in flight gives the loading state`, `F2.AC16 a trip request that fails, other than not-found, gives the failed state`, `F2.AC16 not-found is not shown as a failure`, `F2.R7 formats 2026-11-18 in the user's time zone as 18 Nov 2026`, `F2.R7 uses the same format for a different time zone`, `F2.AC9 cancel does not call delete`, `F2.AC10 confirm calls delete`. `tests/domain/trip-messages.test.ts`: `F2.AC2 blank-name copy matches the approved text`, `F2.AC3 length copy matches the approved text`, `F2.AC8 not-found copy matches the approved text`, `F2.AC10 delete dialog copy matches the approved text`, `F2.AC15 list loading and failure copy match the approved text`, `F2.AC16 trip loading and failure copy match the approved text`.
- **Done when:** `npm test` passes both files. The date tests use fixed instants, not the clock.

### F2.T3 — Trip store port and fake
- **Files:** `app/src/ports/trip-store.ts`, `app/tests/fakes/in-memory-trip-store.ts`
- **Depends on:** F1.T4, F1.T5
- **Work:** `TripStore` interface: `listByOwner(ownerId): Promise<TripRecord[]>`, `create(record): Promise<void>`, `findForOwner(ownerId, tripId): Promise<TripRecord | null>`, `deleteForOwner(ownerId, tripId): Promise<boolean>`. `TripRecord = { id, ownerId, name, createdAt: Date }`. The contract: every method takes the owner id, and `deleteForOwner` removes the trip and its children together and returns `false` when nothing matched. `InMemoryTripStore` keeps records in a Map and exposes `records`, `writeCount`, `listCalls` and `deleteCalls`, so tests can prove that nothing was written or queried.
- **Tests:** None. Interface and test helper, exercised by T4–T6.
- **Done when:** `npm run build` type-checks with the files present.

### F2.T4 — Create-trip service
- **Files:** `app/src/services/create-trip.ts`, `app/tests/services/create-trip.test.ts`
- **Depends on:** F2.T1, F2.T3, F1.T15 (`requireUser`), F1.T5
- **Work:** `createTrip({ session, trips, now, newId, logger }, input)`. Call `requireUser({ session, now })` first; if it fails, return `{ ok: false, error: "not_logged_in" }` and write nothing. Read only `input.name` and run `validateTripName`; on failure return the code and write nothing. Otherwise create a record with `ownerId` from the session user, `id: newId()`, `createdAt: now()`, and the trimmed name. Log `{ tripId, ownerId }` with the message "trip created", never the name. Return `{ ok: true, trip }`.
- **Tests:** `tests/services/create-trip.test.ts`: `F2.AC1 creates a trip owned by the session user`, `F2.AC1 ignores an owner id sent in the request`, `F2.AC2 writes nothing for a blank name`, `F2.AC3 writes nothing for a name over 100 characters`, `F2.AC4 saves the trimmed name`, `F2.AC5 saves two trips with the same name for one user`, `F2.AC12 refuses a request with no session and writes nothing`.
- **Done when:** `npm test` passes the file.

### F2.T6 — Get-trip and delete-trip services
- **Files:** `app/src/services/get-trip.ts`, `app/src/services/delete-trip.ts`, `app/tests/services/get-trip.test.ts`, `app/tests/services/delete-trip.test.ts`
- **Depends on:** F2.T3, F1.T15

### F2.T8 — Drizzle trip store
- **Files:** `app/src/db/trip-store.ts`
- **Depends on:** F2.T3, F2.T7
- **Work:** `createTripStore(db)` returns a `TripStore`. Every query uses Drizzle's parameterised builders. `listByOwner` filters `owner_id = ?` and orders by `created_at` descending. `findForOwner` filters on both `id` and `owner_id`. `deleteForOwner` runs inside `db.transaction` and deletes `trips` where both `id` and `owner_id` match, then returns whether a row changed. Cascades come from the foreign keys in T7. Errors are rethrown, not swallowed.
- **Tests:** None. Checked in code review: every query filters on `owner_id`, no SQL is built from strings, the delete is in one transaction, and errors are not swallowed (CLAUDE.md › Folder layout; project-rules.md › Testing).
- **Done when:** code review passes, and a manual delete of a trip with a child row (added in F3) removes that row.
