# F1 — Registration and login · Plan

_Status: Approved · Last updated: 2026-11-19 · Spec: [F1-registration-and-login.md](../specs/features/F1-registration-and-login.md) (Approved 2026-11-19)_

## Approach
This feature builds the project skeleton and the identity layer that every later feature uses. Pure rules (email and password checks, return-path check, UI copy) go in `src/domain/` with no imports from the database, Next.js, iron-session or argon2. Register, login and logout are services in `src/services/` that receive their stores, hasher, session, logger, clock and id generator as arguments, so unit tests pass fakes. The concrete adapters (Drizzle user store, `@node-rs/argon2` hasher, iron-session cookie) live in `src/db/` and `src/auth/`, and the Next.js routes, middleware and pages in `src/app/` only parse requests and call services. Sessions are an iron-session sealed cookie with no expiry, so no session table is needed. The session data carries the login time, and a session is refused 14 days after login (F1.R8, F1.AC14). That rule is a pure function in `src/domain/session-age.ts`; iron-session's `ttl` is set to the same 14 days as a backstop. The ownership check for trip endpoints is `requireUser` (F1.R10), which F2 to F6 call before any trip query.

## Data model changes
One new table, `users` (migration generated by Drizzle, human approval required):

| Column | Type | Constraints |
|---|---|---|
| `id` | TEXT | PRIMARY KEY (UUID from the id generator) |
| `email` | TEXT | NOT NULL, UNIQUE, CHECK (`email = lower(email)`) |
| `password_hash` | TEXT | NOT NULL (argon2id hash string, never the password) |
| `created_at` | TEXT | NOT NULL (ISO 8601, UTC, for example `2026-11-19T10:00:00.000Z`) |

No cascades in F1. Trip tables and their cascading deletes come with F2.

## Routes and API
All under `/api/auth/`. Bodies are JSON. Errors use the shape `{ "error": { "code": string, "field"?: "email" | "password" | "confirm" } }`.

| Method and path | Request | Success | Errors |
|---|---|---|---|
| `POST /api/auth/register` | `{ email, password, confirm }` | `201 { "ok": true }` | `400` with `code` `required`, `invalid_email`, `password_length` or `password_mismatch` (with `field`); `409` with `code` `email_taken`, `field` `email` (F1.R3 allows this message); `400` `invalid_body` for unparseable JSON |
| `POST /api/auth/login` | `{ email, password, next? }` | `200 { "redirectTo": string }` (`next` after `safeReturnTarget`, else `/trips`); starts the session cookie | `401` with `code` `invalid_credentials` for both unknown email and wrong password (F1.R6) |
| `POST /api/auth/logout` | none | `200 { "ok": true }`, ends the session; also `200` when there is no session | none |

Middleware (not an API) redirects logged-out requests for protected paths to `/login?next=<path>`.

## Screens
- **Register** (`/register`): fields Email, Password, Confirm password, each with a visible label. States: idle; field errors (copy from `auth-messages.ts`, linked with `aria-describedby`, focus moves to the first errored field); email taken (error on the email field); loading (submit disabled, no loading copy). On success, go to `/login`.
- **Log in** (`/login`): fields Email, Password. States: idle; failed (the one message "Email or password is incorrect."); logged-out notice when `?loggedOut=1` ("You are logged out."); loading (submit disabled). On success, go to `redirectTo`.
- **Placeholder** (`/trips`, protected): text that the trips list comes in F2, plus a Log out button. Logging out goes to `/login?loggedOut=1`. The root `/` redirects to `/trips`.

No show/hide password control (spec Accessibility). Plain masked inputs.

### F1.T3 — Domain validation
- **Files:** `app/src/domain/validation.ts`
- **Depends on:** F1.T1
- **Work:** Pure functions. `normalizeEmail(raw)` trims surrounding spaces and lowercases. `isValidEmail(email)` checks the basic `name@domain` format with the regex `^[^\s@]+@[^\s@]+\.[^\s@]+$`. `passwordLength(pw)` counts code points (`[...pw].length`), so emoji count as one character. `validateRegistration({ email, password, confirm })` returns `{ ok: true, email, password }` or `{ ok: false, errors: [{ field, code }] }` with codes `required`, `invalid_email`, `password_length`, `password_mismatch`. - **Tests:** `tests/domain/validation.test.ts`: `F1.AC2 refuses a password of 7 characters`, `F1.AC2 refuses a password of 73 characters`, `F1.AC2 accepts passwords of 8 and 72 characters`, `F1.AC2 counts spaces as characters`, `F1.AC3 refuses a mismatched confirmation`, `F1.AC3 treats trailing spaces as a difference`, `F1.AC13 rejects an email without an @ or domain`, `F1.AC13 normalises a mixed-case email to lowercase`.

### F1.T14 — Login service
- **Files:** `app/src/services/login.ts`, `app/tests/services/login.test.ts`
